# Import Status

## Quick Reference

**Import status** tells you what operations were applied and what's pending due to missing dependencies. Essential for handling out-of-order updates in distributed systems.

## Status Structure

```ts twoslash
interface ImportStatus {
  success: Map<PeerID, CounterSpan>; // What was integrated into history
  pending: Map<PeerID, CounterSpan> | null; // What still needs dependencies
}

type PeerID = `${number}`;
type CounterSpan = {
  start: number; // Inclusive
  end: number;   // Exclusive (e.g., 0-50 = ops 0-49)
};
```

Both fields are present in the WASM and pure TypeScript implementations.
`pending` is `null` when the import reports no pending operations. These ranges
are JavaScript `Map` values: use `.size`, `.get(peerId)`, or iteration;
`Object.keys()` does not enumerate Map entries.

`ImportStatus` reports an import result, not a complete query of the document's
pending queue; `pending === null` does not guarantee that no earlier imports
remain pending. Use the **unreleased** [`exportPendingUpdates()`](/docs/api/js#LoroDoc.exportPendingUpdates)
to export all currently received but unintegrated operations; `undefined` means
that queue is empty, not that the document is synced.


## Pending Operations

Operations become pending when they depend on missing operations (causal dependencies).
These are imported remote operations, not local edits waiting for `commit()`.
Normal snapshot and update exports exclude them. The unreleased
[`exportPendingUpdates()`](/docs/api/js#LoroDoc.exportPendingUpdates) API exports
them separately for persistence; see the [checkpoint and recovery example](/docs/tutorial/persistence#persisting-pending-imports-unreleased).
Restoring those bytes with ordinary `import()` preserves the pending operations,
but they apply only after their actual missing dependencies arrive.

### Common Scenario: Out-of-Order Delivery

```ts twoslash
import { LoroDoc } from "loro-crdt";
import { expect } from "expect";
// ---cut---
const doc = new LoroDoc();

// Peer A creates ops 0-4, then 5-10
const peerA = new LoroDoc();
peerA.getText("text").insert(0, "Hello");
const update1 = peerA.export({ mode: "update" });
const afterUpdate1 = peerA.oplogVersion();

peerA.getText("text").insert(5, " World");
const update2 = peerA.export({ mode: "update", from: afterUpdate1 });

// If update2 arrives first:
const status = doc.import(update2);
expect(status.success).toBeInstanceOf(Map);
expect(status.pending).toBeInstanceOf(Map);
expect(status.pending?.size).toBeGreaterThan(0); // Ops 5-10 need ops 0-4.
expect(doc.getText("text").toString()).toBe("");

// Import missing dependencies:
const completed = doc.import(update1); // Both updates now applied
expect(completed.pending).toBeNull();
expect(doc.getText("text").toString()).toBe("Hello World");
```

## Handling Pending Operations

```ts twoslash
import { LoroDoc, VersionVector } from "loro-crdt";
// ---cut---
async function handleImport(
  doc: LoroDoc,
  update: Uint8Array,
  fetchMissing: (from: VersionVector) => Promise<Uint8Array>
) {
  const status = doc.import(update);
  
  if (status.pending !== null && status.pending.size > 0) {
    const missing = await fetchMissing(doc.version());
    doc.import(missing);
  }
}
```


## Best Practices

### Always Check Status

```ts twoslash no_run
import { LoroDoc } from "loro-crdt";
const update = new Uint8Array();
// ---cut---
const doc = new LoroDoc();
const status = doc.import(update);
if (status.pending !== null && status.pending.size > 0) {
  console.warn("Operations pending:", status.pending);
  // Fetch missing updates
}
```

### Use Batch Import
```ts twoslash
import { LoroDoc } from "loro-crdt";
// ---cut---
const updates: Uint8Array[] = [
  //...
];
const doc = new LoroDoc();
const batchStatus = doc.importBatch(updates);
// Single status check for all updates
```
